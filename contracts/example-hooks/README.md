# `contracts/example-hooks/` — vendored example hooks (NOT the core tool)

This directory is **not part of the simulator's core**. It holds real,
third-party Uniswap v4 hooks, vendored verbatim, used purely as **worked
examples and test fixtures** to prove the simulator can run a real published
hook end-to-end.

## The core is hook-agnostic

The simulator does not know or care about any specific hook. Its general entry
point is:

```bash
v4sim-replay --hook path/to/out/MyHook.sol/MyHook.json --hook-flags 0x<bits>
v4sim-report --hook path/to/out/MyHook.sol/MyHook.json --hook-flags 0x<bits>
```

That deploys *any* hook bytecode at a mined, flag-valid address, attaches it to
a fresh pool, and replays real historical swaps through it — measuring LP
returns (HODL / IL / fees / gas / LVR) the same way for every hook. The bundled
`--antisandwich` flag is merely a convenience preset that points `--hook` at the
example below.

> The AntiSandwich and ReHypothecation files are **vendored verbatim** (MIT, see

> (for ERC-4626 etc.) is the `oz/` git submodule, pinned to the commit
> uniswap-hooks uses.

`out/` (forge build output) is git-ignored and regenerated by
`scripts/build_contracts.sh`, which builds this project *after* `contracts/v4-core`
so the hook links against the exact v4-core the harness deploys.

## Where a hook fits on the generality ladder

| Tier | Hook shape | What the simulator needs | Example |
|------|-----------|--------------------------|---------|
| 0 | self-contained, standard LP position, standard accounting | nothing — just `--hook` | ✅ `AntiSandwichHook` |
| 1 | calls external contracts (oracle, Chainlink, ERC-4626, …) | mocks deployed in the env (`WorldSpec.env_setup` + `hook_ctor_args_fn`) | ✅ `OracleGuardHook` |
| 2 | owns / relocates liquidity, or has extra value sources | a `HookAdapter` subclass that drives its verbs and values the LP's stake (`manages_own_liquidity`, extensible attribution) | ✅ `ReHypothecationHook` |

**Tier 0 — AntiSandwich** touches no external contracts and leaves the LP as a
standard range position, so it needed zero hook-specific accounting — its effect
(donations → LP fee growth, constrained arbs → lower LVR) flows through the
existing metrics.

**Tier 1 — OracleGuard** reads a Chainlink-style feed on every swap. The feed is
an external dependency, so the world's spec deploys a `MockV3Aggregator` via
`WorldSpec.env_setup` and wires its address into the hook's constructor via
`WorldSpec.hook_ctor_args_fn` (see `oracle_guard_hook_spec()` in
`src/v4sim/replay/runner.py`). Run it with `v4sim-replay --oracle-guard` /
`v4sim-report --oracle-guard`. With the default price ($2500) above the floor
($1) the breaker stays off and the hook is transparent; raise the floor above
the price to watch it pause every swap.

**Tier 2 — ReHypothecation** owns the LP's liquidity: the LP deposits via
`addReHypothecatedLiquidity` and holds the hook's ERC-20 shares, while the
underlying sits in ERC-4626 vaults and is JIT-injected during swaps. The
`ReHypothecationAdapter` (`manages_own_liquidity=True`) makes the runner skip the
router position — `setup()` deposits through the hook and `extra_value_usdc()`
values the stake via `previewRedeem` (principal drives IL; fees/yield go to the
fees column). `env_setup` deploys the two vaults. Because the hook JIT-`take`s
its owed tokens before the swapper settles, the PoolManager needs standing
reserves: the adapter places a `seed_frac` (default 1×) full-range backstop —
the co-existing pool liquidity the hook needs in practice — whose fees are *not*
counted for the hook, so it earns only its proportional share. Run with
`v4sim-replay --rehypothecation` / `v4sim-report --rehypothecation`. (Vault yield
is 1:1 by default; modelling an APY by crediting the vaults over time is the
natural next knob to surface the "yield on idle capital" upside.)

## Adding another example hook

1. Drop the hook + its dependencies under `src/` (and any non-v4-core libs under
   `vendor/`), preserving import paths. Record provenance in `NOTICE`.
2. `scripts/build_contracts.sh` compiles it to `out/<Hook>.sol/<Hook>.json`.
3. Run it generically with `--hook out/<Hook>.sol/<Hook>.json --hook-flags <bits>`
   (bits must match the hook's `getHookPermissions`), or add a small preset like
   `antisandwich_hook_spec()` in `src/v4sim/replay/runner.py`.
4. Tier 1/2 hooks additionally need mocks and/or a `HookAdapter` subclass — see
   `src/v4sim/strategies/hook_adapter.py`.
